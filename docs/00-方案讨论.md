## 0. 一句话

你要的不是"更聪明的 AI"，是"更常停下来想的人"。插件的第一职责是让你停，第二职责才是给你材料。

## 1. 三个症状，三种干预

| 症状 | 真正缺的动作 | 干预时机 | 哪种形态覆盖 |
|---|---|---|---|
| 读文献没有自己的想法 | 生成一个属于自己的判断 | 读完之后 | 台账 |
| 把别人/AI 的内容当客观事实 | 标出来源与证据等级 | 读、写的同时 | 台账 + 技能包 |
| 自己的想法没有明确目的 | 说清目的、成功判据、放弃条件 | 动手之前 | 门禁 / 开关 / 预设 |

【判断】没有一种形态能同时覆盖三行。所以"插件"大概率不是一个东西，而是"一个拦截器 + 一个台账 + 一套题库"。

## 2. 四条设计底线

1. **只提问，不代答。** 如果插件替你写"你的观点可能是 X"，你很可能把 X 当成自己的想法——这正好复制了你要治的病。
2. **反驳者也要被反驳。** 每张决策卡要记录"这次质疑是否成立"。否则你只是把权威从文献换成了插件。
3. **来源分级。** 插件自己说的话也要标：查到的 / 推断的 / 不知道。它不能用幻觉反驳你。
4. **可退出。** 任何强制门禁都要能一键绕过。不能退出的工具，最后会被整个关掉。

## 3. 能力边界

- **【事实】** DSH 插件挂在 DSH 的会话生命周期上：你发给 DSH 的消息、DSH 调用的工具、DSH 的 Web 界面。
- **【判断】** 你在 Zotero 里读 PDF、在 Word 里写论文、在组会上发言时，它不在场。
- **含义**：如果目标只是"和 DSH 协作时别盲从"，插件够用；如果包括"读文献时形成自己的判断"，插件只能做"读完之后强制写卡片"，读的过程管不到。后者需要 Zotero/浏览器一侧的工具，或者一个不依赖软件的习惯。

## 4. 实现强度：三种"拦得住"的程度

| 强度 | 做法 | 模型能否绕过 | 成本 |
|---|---|---|---|
| L1 | 系统提示词常驻一段"先追问再动手" | 能：忽略、敷衍、写套话 | 最低 |
| L2 | `agent/pre-step` 钩子，在模型看到前插入门禁指令 | 难，但仍可敷衍 | 中 |
| L3 | 插件自己弹问题 + 未回答不许调工具 | 不能 | 最高，需原型 |

- **【事实】** DSH 提供 `agent/pre-step`（可替换进入该步的消息）、`tools/pre-execute`（可拒绝工具执行）、`userQuestions`（可发起提问）、`commands`（可注册斜杠命令）。
- **【待验证】** 在 pre-step 里同步提问是否与 UI/超时冲突；替换消息后模型行为是否稳定；L3 的工具闸门会不会让模型陷入重试。

【判断】L1 的性价比最高，但最容易变成仪式；L3 最可靠，但最重、最容易误伤。建议 v1 用 L2，把 L3 作为"你连续两周敷衍门禁"后的升级项。

## 5. 五种形态

### A. 常驻"思辨门"

- **机制**：每条消息在模型动手前被拦下；门禁问三件事（目的与判据 / 假设与证据 / 替代路径）；答完才放行。
- **嵌入**：你什么都不用记得。适合"推进实验、改代码、下结论"这种一抬手就干的时刻。
- **优点**：唯一不依赖自觉的形态；把"停一下"变成默认。
- **代价**：吵；琐事也拦；模型会学会写像样的套话；你也会学会点"继续"。
- **反仪式**：每周至少一次要求你用文字回答（不给选项）；卡片记录"质疑是否成立"。
- **强度**：L2 或 L3。

### B. 会话开关 + 斜杠命令

- **机制**：`/思辨 on|off` 开关；`/辩 <一句话>` 单次强制；只影响本会话。
- **嵌入**：开工前一个动作，像系安全带。适合"今天要推这个实验"。
- **优点**：不污染别的会话；可控、可逆；实现最轻。
- **代价**：靠你记得开——而"忘了想"正是病灶；两周后大概率吃灰。
- **强度**：L1/L2 + 命令。

### C. "诘问者"预设

- **机制**：独立 agent preset，系统提示只有审问；你切过去被问完，再切回执行会话。
- **嵌入**：像找同门聊十分钟再动手。适合"要不要调研这个方向""这个方案值不值得"。
- **优点**：人格纯粹、上下文干净、不干扰执行；几乎不写代码。
- **代价**：要搬上下文；小事不会去用；两个会话记忆不共享。
- **强度**：L1。

### D. 决策台账

- **机制**：卡片四栏——来源（文献原文/文献转述/AI 生成/我的推断）、证据、我的判断、状态（待验证/已证实/已推翻），落本地 Markdown。先做文件 + 命令，验证有人填，再做 Web 面板。
- **嵌入**：读完一篇、开完组会、写引言之前。
- **优点**：直接治"把二手当事实"；可复盘、可统计；产物属于你。
- **代价**：不拦当下；维护成本高；容易变成填表作业。
- **强度**：L1（提醒）+ 文件。

### E. 技能包（不装插件）

- **机制**：一份 `SKILL.md` + 几个模板，放进 skills 目录。
- **优点**：零安装、可移植、改词快。
- **代价**：只在被触发时生效；约束最弱。
- **适合**：先验证题库好不好用，再决定是否工程化。

## 6. 建议的 v1

**B 的开关 + A 的门禁（L2）+ D 的最小台账（每次放行追加 5 行）。**

理由：

1. 先用最低成本验证"这套问题问得值不值"，而不是先造一个常驻系统。
2. 开关让你能对比"开/关"两种状态的产出——这本身就是一次实验。
3. 台账是唯一能留下证据的部分。没有它，三个月后你无法判断插件有没有用。
4. 不做 Web 面板、不做自动查文献：前者是包装；后者会引入"AI 用幻觉反驳你"的新问题。

如果你觉得 v1 还是重，退到 E：先只验证题库，一周后再决定要不要工程化。

## 8. 题库草稿（地磁导航）

> 这是初稿，不是标准答案。你删掉的题，比留下的题更能说明你想要什么。

**选题 / 方向**

- 你要解决的是"没有 GNSS 时还能定位"，还是其中一个子问题（精度、实时性、抗干扰、初始化、可解释性）？只能选一个指标变好，你选哪个？
- 这个方向现在缺的是方法、数据、还是评测基准？你怎么知道缺的是这个？
- 你的"新"是相对谁新？最近三年最接近的三篇是什么？读完了吗？

**判断是否值得调研**

- 这次调研要回答哪个具体问题？如果调研完答案仍是"看情况"，算失败吗？
- 你已经知道什么？哪条是文献结论，哪条是你的推测？分开写。
- 如果结论是"这条路不通"，你会放弃吗？现在先写下放弃条件。

**实验 / 方法**

- 方法的物理假设是什么（地磁场时空相关长度、磁测噪声、载体磁干扰、日变改正）？哪个假设最容易被你的数据打破？
- 基线是谁？ICCP、匹配滤波、还是深度学习方法？为什么是它？
- 成功判据是哪个数、哪个数据集、多少算成功？现在写，别等跑完再定。
- 如果结果比基线差，你的第一解释是什么？有没有可能这个解释是事后编的？

**写作 / 结论**

- 这句话是文献原话、你的转述，还是 AI 生成的？读者能顺着它找到原文吗？
- 这个结论在你的实验条件下成立，还是在别人的条件下成立？迁移代价是什么？
- 审稿人最可能攻击哪一点？为什么不先补上？

**通用**

- 为什么是现在，不是下周？
- 如果只能保留一半，砍哪一半？
- 有没有一个更便宜的实验能先否掉这个想法？
